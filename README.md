# 西行·玄奘 3D（xuanzang-3d）

3D 版玄奘西行。核心不是战斗，是**氛围**：一个人在塔克拉玛干里走，
看不见边、看不见路、看不见尽头。引擎 Godot 4.7.2（Forward+）。

## 怎么跑

```powershell
$godot = 'E:\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe'
& $godot --path E:\development\xuanzang-3d
```

也可以直接用 Godot 打开本目录按 F5。

### 操作

| 动作 | 键 |
|---|---|
| 行走 | `W` `A` `S` `D` 或方向键 |
| 冲刺（更耗体力，但**跑反而走不远**） | `Shift` |
| 倒下之后再走一次 | `R` |
| 释放/抓回鼠标 | `Esc` |

## 怎么验证

```powershell
& $godot --headless --path E:\development\xuanzang-3d tests/test_scene.tscn
```

输出 `ALL TESTS PASSED (217 项)`、退出码 0（项数会随契约增加，认这行字就行）。

必须是**场景**跑法。`--script` 模式不注册 autoload，引用 `GameState` 的脚本
连编译都过不了。

想看一眼画面（会短暂弹出窗口）：

```powershell
& $godot --path E:\development\xuanzang-3d --resolution 1600x900 `
    tools/capture.tscn -- --out D:\shot.png --frames 110 --walk 2.6
```

截图探针的常用参数：`--walk <米/秒>`（让行者真的走起来——**走路那一身晃只在
移动时存在**，站着拍是拍不到的）、`--collapsed <秒>`（定格倒下之后的第几秒：
伸手、闭眼、题记全挂在这条时间线上）、`--storm`、`--tired`、
`--player-x <米>`（沿 +X 挪出去验"沙漠还有没有边"）。

## 氛围设计

塔克拉玛干的可怕不来自怪物，来自四件事。每一件都落成了可断言的机制：

| 感受 | 手段 | 在哪 |
|---|---|---|
| 无参照 | 沙丘脊线单调重复，没有地标 | `dune_field.gd` |
| 无边界 | 距离雾把远处溶进天空色，地平线消失 | `desert_world.gd` 的 fog |
| 无退路 | 体力 215 秒见底（一局约 190 秒 / 490 m），冲刺与沙暴都会更快 | `game_state.gd` |
| 压迫 | 沙暴周期：平静 → 起风 → 压顶 → 退去；一阵阵的**大风吹**（推人、歪镜头、扑沙） | `sandstorm.gd` |

沙暴同时改四样东西，且四样指向同一个感受——看不清、走不动、心里发慌：
雾浓度、天光、风力推挤（玩家被动位移）、掉体力的速度。

## 走不出去的那一局

第一版给了**无限拼接的沙漠**，队友（也是我）走出去以后，需求方的判词是：
"我操，我走出沙漠了？"——"无限"是个工程答案，不是这一关要的东西。
这一关要的是**走得出去的画面，走不出去的结局**：

| 契约 | 数 | 谁守着 |
|---|---|---|
| 翻得过 4 道沙丘 | 无风 492 m / 顶风 453 m，两种都翻过 5 道脊 | `[体力契约]`、`[风里的一局]` |
| 走三分钟左右 | 实测 189 s 倒下（165~205 s） | `[体力契约]` |
| 地形够大到看不见边 | 一整块 4096 m 见方；最坏走位离最近的边还剩 1648 m，雾在 1 km 处只剩 25% 透射 | `[地形够不够大]` |
| 累了要喘 | 频率 0.24→0.90 Hz、幅度 1.4→5.2 cm，倒下后先急喘再慢下来 | `[喘气]` |
| 累了镜头要晃 | **每一步**一下陷（3.2~5.5 cm）、左右 ≤1.8 cm、滚转 ≤1.26° | `[步态：一脚一步]` |
| 倒下之后 | 2.6 s 侧倒 → 1.6 s 喘 → 5.5 s 眼睑合拢 → 12 s 出题记 | `[倒下时间线]` |
| 闭眼前伸手 | 右手伸向佛的胸怀，2.8 s 转头 + 3.2 s 伸手，全程有颤 | `[主场景组装]` |

### 三个"反直觉"的地方

1. **沙丘脊距 95 m，不是 190 m。** 老公式写的是 `phase = (x / spacing) * PI`，
   而 `cos` 的周期是 2π——参数名说的是 95，实际脊距是 190，测试按 95 记账，
   于是"三分钟翻 4 道脊"这条契约永远差一道。改成 `TAU` 之后名副其实，
   丘高也从 30 m 收到 20 m（保住同一个坡度，不然脊距减半就成了一堵墙）。
2. **走路晃的主犯是滚转，不是左右摆。** 上一版给了 2.6° 的滚转和 3.4 cm 的
   左右，却只给 5 cm 的上下——把轻重搞反了。沙地里走路，第一读数永远是
   "每一步踩下去"，镜头一歪整个世界都歪，那才是"左摇右摆太过了"。
3. **"不机械"不等于"真随机"。** 上一版用两条正弦叠步态，两个毛病同源：
   正弦天生周期、天生对称。现在改成**按步号哈希**：看着随机，但同样的输入
   走出同一条路——截图探针的同参数同构图靠的就是这条。

### 临终那只手为什么这么难做

**手指指向佛，而相机也指向佛——眼睛、手、佛三点共线。**
第一版就是这么画的，结果我们是从**正后方**看这只手：手指全部朝向画面深处，
逆光剪影里只剩两三个小凸起（需求方："你做的那个手啊，有点抽象"）。

两个修正，缺一不可：

- **腕点推到画面右下角**（`WRIST_OFFSET`）：让"眼→腕"和"腕→佛"成 ~70°，
  手才第一次以侧面出现在画面里；
- **把扁平的那一面解到朝向镜头**（`HAND_FACE_SOLVE`）：手是扁的，
  姿态不能交给"世界朝上"决定，要在垂直于手指的平面里取"眼→手"的投影当法线。

比例也按真手重做了一遍：掌 10×11.5 cm、掌厚 3.7 cm、前臂 40 cm。
上一版把袖子做到了 95 cm、袖根半径 13 cm，离眼睛最近的那一截先糊住半个画面。

## 大风吹

沙暴改了雾、天光和掉体力的速度，需求方看完只有一句："大风吹的感觉不是很明显，
视觉和行走上。"——雾浓了、天暗了，是**天气**；被推、被歪、被沙扑，才是**风**。

风的全部读数只有**一个数**：`GameState.wind_force = 沙暴强度 × 阵风包络`。
三样东西都读它，所以"沙扑上来"和"人被推了一下"永远同时发生：

| 风推在哪 | 手段 | 谁守着 |
|---|---|---|
| 人（被推着走） | 峰值 2.6 m/s 的推力，**横向占 97%**（顺风只让人走得快，不叫风） | `[风是横着抽的]`、`[风里的一局]` |
| 人（走不动） | 顶风步速 ×0.65、顺风 ×1.10、横风 ×1.00；满风时步长缩 15%（小碎步） | `[顶风走得慢]`、`[风里步子更碎]` |
| 镜头 | 脑袋偏移 0.16 m、地平线滚转 2.6°、俯仰 2.2°，阵风上升沿还会跄一步 | `[风推在镜头上]` |
| 沙 | 沙带顺风跑（0.45 + 4.5×force）、沿流向拖影、浓度 ×(0.72 + 0.55×force) | `[风里的沙带看得见吗]` |

"被推着走"和"走不动"是两件事，上一版只有前者：玩家按着前进键，脚下却是空的，
读出来是"被平移了半个身位"。现在`Wanderer.wind_speed_scale`是**唯一的实现**，
游戏和 `[风里的一局]` 那条平衡测试读的是同一个函数——各写一份的话，
测出来的一局和玩到的一局会分家，而分家的那天没人会知道。

默认那阵风是 (-0.22, 0, 0.98)：横向 97%，逆风只有 22%。所以朝弥勒走（+X）时
满风步速乘 **0.923**——够读出"顶着风走费劲"，又不至于把三分钟四道沙丘吃掉
（真实的一局：无风 492 m / 有风 453 m，都翻过 5 道脊）。

阵风包络是**两个不可通约的慢频率相乘再取幂**（0.63 和 0.29 rad/s，取 1.6 次方）：
一波扑上来、缓一缓、又一波。用 `_timer` 当相位是从上一版抄过来的错——它每换一个
沙暴相位就归零，于是"一阵一阵"变成"每过一关抖一下"，所以另立了一个单调时钟。

### 一层画不出来的沙

"整个场景一直飘着带状的沙尘"这层沙，`shaders/desert_post.gdshader` 里那几个数
曾经算得很漂亮、写得很整齐——**而整整一层是看不见的**。

原因是门槛：噪声取高处当沙丝，门槛写了 `0.54 → 0.82`，看着离中值 0.5 不远。
但这个 fbm 的实测分布是**均值 0.415、σ 0.136**（四个八度之间带旋转，分布会偏），
于是那两个数落在 **+1σ → +3σ** 上：只有千分之几的像素够得着，剩下的全被截掉。
而"看不见"和"没写"在截图上是同一个样子——靠看图 review 永远抓不住。

所以现在有了一条不看图、只算数的测试 `[风里的沙带看得见吗]`：它从 shader 源码里
**抠出**归一化的均值/标准差、σ 门槛和采样频率，再用同一套噪声铺满一屏量一遍覆盖
面积，要求"薄沙铺开 20%~90%、实心沙丝 1%~35%"。任何一边被改歪都会红。

同一层还踩过另外两个坑，都留在就地注释里：

- **硬边不能用**。有个版本为了让"顶着风走、沙迎面扑来"更真，把采样挪到世界坐标的
  水平幕上，用 `smoothstep(0.50, 0.68)` 卡出硬边——半个画面都在带里，出来的是
  满屏平行的硬线，划过佛像和城郭像镜头被划伤（需求方："很不自然"）。
- **速度比浓度更像风**。上一版不管刮多大风，沙的漂移都是同一个速度，"大风吹"
  在画面上只剩"雾更浓了"。现在平静时沙带自己慢慢漂、满风时乘 4.95，再加一道
  沿流向的拖影——**静帧里唯一读得出速度的线索就是被拖糊的那一条边**。

## 沙面、颗粒、风声

成片交出去之后又收到三条，都落在**最难自证**的地方：脚下的沙太空、颗粒看着像
一层布纹、风只有画面没有声音。三条都不是"再加点东西"，是**先量**。

### 脚下的沙：一张贴图是画不出风向的

原来那片沙是一张 **25 cm 的 Perlin 法线贴图**。它在别处没问题，在这一关等于
不存在——**太阳在弥勒背后、几乎正对着视线，逆光里漫反射对法线几乎不敏感**
（`N·L` 整片都接近同一个值，法线怎么歪都不改明暗）。而人眼认"沙"靠的恰恰是
两样**不靠漫反射**的东西：

1. **脊线的走向**。风成沙纹是一道道**垂直于风**的横向小坡：脊线是弯的、
   迎风面缓、背风面陡。各向同性的 Perlin 长得像橡皮泥，怎么调都不像风做的。
2. **沟里的暗**。沙纹的读数是"亮脊 + 暗沟"的交替，那是**环境光遮蔽**，
   跟漫反射无关，所以逆光下它照样在。

于是 `shaders/sand_ground.gdshader` 不用贴图，直接解析地算高度场再取有限差分：
远的一层 **62 cm** 管大面，近的一层 **9 cm** 顺风排列管脚下（3 m 内满强度、
18 m 外彻底淡出，否则细纹在远处不到一个像素宽，变成闪烁的摩尔纹），再叠
**3 cm** 的砂粒。剖面用 `pow(..., 1.8)` 削出尖脊；脊距本身也跟着一层低频噪声
起伏（`0.72 + 0.60 × 噪声`），不然整片沙像一块印花布。尺度是量过的：
塔克拉玛干的风成沙纹脊距多在 5~15 cm、脊高 1~2 cm。

风向不写死：`desert_world.set_wind()` 把 `GameState.wind_direction` /
`wind_force` 喂进 shader——**和推人的那股风、和把镜头吹歪的那股风是同一个数**，
所以风一大，脚下的沙纹也跟着变深。

两条踩过的坑（都留在 shader 的就地注释里）：

- **别拿法线的 y 分量去判"这是沟"**。沙丘自己就有坡度，那样整片坡会被判成沟、
  一坡的沙全黑下去。明暗必须来自**同一条相位**的脊值。（试过一次，拍出来就是
  一坡黑。）
- **远处的沟要收着**。62 cm 那层在 100 m 外还有 9 个像素宽，全强度是一片
  "扇骨"——第一版拍出来正是这样。真沙纹越远越糊，因为中间隔着空气；
  这里用距离代掉那层空气（`tone` 从 0.17 起，远处乘 0.32）。

### 颗粒：这一条只能在 GPU 上量

颗粒是几行噪声。它原来用的是那句到处都在用的
`fract(sin(dot(p, vec2(12.9898, 78.233))) * 43758.5453)`，而这句
**在这块 GPU 上不是白噪**，是一片逐像素的花纹——放大 1:1 看，沙面、佛像、
天空上都盖着一层细网格。

排查的时候我把结论推翻过两次，**两次错的都是"证据"那一环**，不是推理那一环：

1. **先用 CPU 证明"哈希没问题"。** 写了一条"相邻像素相关性"的测试，顺手把旧
   写法当对照组，满以为它会红——结果它测出 **0.016**（白噪），结论于是翻成
   "网格是录片的 MJPEG 压出来的"。错在哪：那条测试跑在 CPU 上，GDScript 和
   照抄用的 numpy 都能用 float64 算 `sin`，而真正出图的那一份是 **GPU 上的
   float32**。重测（同一算式、CPU、**float32**、铺满一屏）：旧写法依旧是纯白噪
   （0.10~0.50 四个频带各 **0.250**、相邻相关 0.000）。所以这不是"float32 的
   乘法精度"问题，是 **GPU 那颗 `sin` 在大自变量上的表现**：自变量是
   `43758 × (12.9898x + 78.233y)`，在 1600×900 上到 **10⁹** 量级，硬件做周期化
   的精度已经不足以让相邻像素互相独立。**抄到 CPU 上测，这一层根本不在场。**
2. **再怀疑是编码器。** 同一段片子里取天空那条带，0.40–0.50 cyc/px 的能量占比
   只有 **0.026**，比无损静帧（**0.10**）还低——MJPEG 是把 1 px 颗粒**抹平**的
   那一个，不是造出它的那一个。这也是为什么"在成片里找网格"定位不了问题：
   它出现在无损静帧上，成片里先被吃掉。

真正的判据是**无损静帧 + 同帧只换一处**（1600×900、同一机位、同一个摇法）。
下面是"能量挤在一个窄带上"的程度——白噪应该摊平到每个频带各 0.25，
占比高就是规则花纹：

| 取样区 | 关掉颗粒 | 新哈希 | 旧哈希 |
|---|---|---|---|
| 天空那条带 | 0.024 | 0.102 | **0.292** |
| 沙面带（有沙纹垫底） | 0.172 | 0.213 | **0.486** |

新哈希和"关掉颗粒"同量级，旧哈希是它的三倍——那层网格就在这三倍里。
换掉之后 `[颗粒是白噪，不是布纹]` 守住了这条：实测相邻像素相关性 **0.026**。
那条测试的对照组**不能再用旧哈希**（它在 CPU 上会通过），改成一片
**故意做出来的条纹**（1.000）——先证明这把尺子量得出条纹，再用它去量颗粒。

### 风声：要抬的是频谱，不是音量

风原来只有画面：沙带在跑、人走不直、镜头被吹歪，**而耳朵里是空的**。
风声是吹在观众身上的那一半，缺了它，风只发生在屏幕里面。

`scripts/audio/wind.gd` 与 `breath.gd` 同一路数：`AudioStreamGenerator`
程序化合成，不带素材。音色是物理的两层——低频的"呼——"（远处有东西在滚）
+ 高频的沙沙（沙粒打在空气里、打在衣服上），**低通截止点跟着风力走**
（`0.020 → 0.42`），所以风越大不只是响，是频谱整体往上抬。

实测（`[风声]`，headless 下没有声卡，波形本身可以断言）：

| | 无风 | 半风 | 满风 |
|---|---|---|---|
| RMS | 0.0077 | 0.1222 | 0.6826 |
| 过零率 | 0.005 | 0.094 | 0.348 |

它读的是**同一个数**：`GameState.wind_force`。推人、歪镜头、沙子浓淡、脚下沙纹
的深浅，加上这一层风声，**五样共用一个包络**——沙扑上来的那一刻，人也正好被
推了一下、耳朵里也正好响起来，这才是一场风，不是五个效果。

它和喘气一样跟着眼睑退场（`eye_close_at`），基准音量 `BASE_DB = -12 dB`
压在音乐（-6 dB）之下。**音乐仍然一个字都不掺**（那是被明确要求过的取舍，
见 [docs/design/bgm.md](docs/design/bgm.md)）——分界线是：曲子不许因为世界上
发生了什么而变形，一个会随世界变化的音效应该另起一个播放器。

## 楼兰幻影（海市蜃楼）

沙尘里升起的一座巨城：1500 m 高的主塔、6.6 km 见方的城墙、四角楼、城门楼、
城内小塔群与房屋——**3748 个部件，合并成单个 mesh**（构建 109 ms）。

尺寸是真实佛塔的二十倍。放大了二十倍，细节就必须配得上这个尺度：一百多个部件
堆出来的轮廓只有六七个转折，一看就是"几个圆柱摞起来"。所以细节全部花在
**剪影**上——两公里外真正能被看见的只有轮廓。

### 它走不近

这是海市蜃楼区别于"远处有个模型"的唯一要点。它是光的像，不是实体：玩家朝它走，
它同步后退，那段距离永远不变（测试里的 `[幻影走不近]` 守着这条）。第一版把幻影
钉在固定世界坐标上，走两百多米就穿模进城，错觉当场就碎。

距离 1900 m 是权衡出来的。幻影**自己关掉了 Godot 的雾**、改用材质里的空气衰减，
所以不怕远；真正的顾虑是"近了会变成贴脸放大"——上一版把城摆在 250 m 外，
城墙横切出画外、抬头看见的是穹顶。围住视点和压住视点是一回事，而"围"就是
"室内"，那条路是死的。

### 弥勒大像

幻景的最高点不是塔，是像：犍陀罗立佛白膜（CC0，见
[assets/statue/CREDITS.md](assets/statue/CREDITS.md)）放大 4 倍，
高度 4.3 km，站在城墙前 480 m。像头仰角 66.7°——**故意装不进画面**，
得抬头才看得见。太阳由 `main.gd` 反解到像的正后方，玩家是逆光走向它。

### 佛塔让开了佛

像占了画面左半边（剪影右缘落在方位 0° 附近），而城郭原来的中轴正好也在 0°——
主塔和城门楼**贴着像的右缘**立起来，被挡掉一半。现在城整体右移 800 m
（`Mirage.CITY_SIDE`）：主塔落到 +16.0°、城门楼 +23.6°，让出的天 ≥ 8°
（`Mirage.CITY_CLEARANCE_DEG`，测试里的 `[幻影不是穹顶]` 一节守着这条）。

挪的是**城**，不是像：像和太阳一动不动（太阳是按像的方位反解的，像一挪逆光
就散了）。城因此变成**不对称**的——左端钉在 -2500 m（守"横向量不出来"这条），
右端跟着 CITY_SIDE 一起往右长。

### 诡异感从哪来

- **分层错位**：每 26 m 一层整体水平错开，且三分之一的层大幅断裂、其余几乎不动。
  均匀错位会读成"千层饼"，偶尔断一次才像光路真的折了一下。
- **冷暖走向**：底部被沙尘染成暖褐、顶部是天空的青蓝。单一颜色无论深浅都像塑料。
- **亮度压在中间调**：ACES 色调映射会把高亮度色彩去饱和推向白色——幻影一旦够亮
  就变成一坨白的，那正是"亚克力"观感的来源。
- **边缘溶解**：轮廓被噪声啃掉，而不是一条干净的边。

## 自言自语

> 应该给主角加点自言自语啊……什么的，大唐西域记里，弄一点？

台词表在 `scripts/ui/soliloquy_lines.gd`，十句，**每句都标着出处**——
八句直接取自《大唐西域记》卷十二"大流沙"那一段
（"沙则流漫，聚散随风，人行无迹，遂多迷路。四远茫茫，莫知所指……
乏水草，多热风，风起则人畜惛迷……时闻歌啸，或闻号哭……往来者聚遗骸以记之"），
两句取自《大慈恩寺三藏法师传》（莫贺延碛的"口腹干焦，几将殒绝"
"宁可就西而死，岂归东而生"，以及临终那一愿"愿生睹史多天，见弥勒"）。

**这一关的沙、风、幻影、幻听，史料里一条不缺**——所以台词不用编：
它就是玄奘后来自己写下的那些字。这一局本来就是回忆（倒下之后还要出题记），
回忆里的人当然知道自己后来写了什么，于是"自言自语"和"引文"在这儿是同一件事。

不说白话，也不装作随口一说；每条不超过 18 个字，说一句、淡出、等 11 秒再说下一句。
触发条件只问**状态**（风够大没有、幻影实不实、还剩多少体力、倒下多久），
不问时间——时序（沙暴相位、体力曲线、倒下那十几秒）全在别处已经有了，
两处各写一份迟早会对不上。

### 三个坑

1. **间隔闸门不能摆在 `due()` 开头。** 写成 `if clock - last < MIN_GAP: return -1`
   之后，落下那两句再也进不来——它们在表里特意写了 `gap = 0`（临终那一愿必须
   落在倒下后 1~2.5 秒，最后一句要在闭眼前念完），结果一次都没生效。
   间隔要**按句子**看。
2. **"谁先到期"和"谁排在前面"是两件事。** 录片时抓到：一开局就满风的局里，
   "乏水草，多热风"在第 **0.03 秒**就说了出来，抢在开场白"四远茫茫"前面——
   因为风那条的条件是"风够大"，满风的局里它从第一帧就成立。台词表的顺序管得住
   同时到期，管不住谁先到期，所以另有一条 `OPENING_FLOOR`（开场 12 秒属于第一句）。
3. **时钟必须是单调的。** `GameState.elapsed` 在倒下那一刻就停住了，而倒下去之后
   还有两句话要说——量间隔得用 `elapsed + collapse_elapsed`，不然那两句会
   把自己的间隔算成"永远不够"。

## 一条 48 秒的片子

录片入口是 [tools/record.gd](tools/record.gd)（`--walk 2.6 --peak --look`），
它自带一份**镜头时间表**（`LOOK_KEYS`）。规矩是三条，都为了"宿命感"：
**一镜到底不剪辑**、**只抬头看他从不回头**、**倒下之后头还在往上够**。

| 时刻 | 画面 | 声音 |
|---|---|---|
| 0~5 s | 平视，佛在正前方，走着 | 曲子从 0.4 s 的静音里起拍 |
| ~4 s | 「四远茫茫，莫知所指。」 | |
| 5~8.2 s | **第一次抬头**（→60°）：佛头 + 举身光 | |
| 17.6~21 s | **第二次抬头**（→52°，更慢）：多出肩膀和城 | |
| 24.4~26 s | 只落回 12°——他再没有真正低下头 | |
| ~26.7 s | 腿软、侧倒，头自己转向佛的胸怀 | |
| 33~36.8 s | 眼睑合拢；音乐在 35 s 掉下去 | |
| **36.0 s** | **音乐撞回来（高潮），画面正在全黑** | |
| ~38.7 s | 题记 + 「R　再走一次」 | |
| 48 s | 收（题记之后留 9 s 给人读） | |

这张表是**倒排**出来的：BGM 通篇是一堵音墙（-8~-12 dB），唯一的结构点在
34.5~35.5 s 掉下去、36 s 撞回来。要让"全黑"压在那个点上，倒下就得在 26.3 s
左右——倒下的那一刻起，眼睑用 4.2 + 5.5 s 合拢。这局体力实测掉约 0.0094/s，
所以起点体力定 0.25。**这是整条片子里唯一"刻意"的地方**，也是它为什么必须
录两分钟而不是随手截一段。

### 字幕为什么是 60 px

不是"看着差不多"，是**从手机屏上反推的**：

1. 出的是 1600×900 的 16:9；抖音竖屏信息流按**宽度**铺满，
   缩放比 = 1080 / 1600 = **0.675**，屏上字号 = 字号 × 0.675；
2. 抖音自己的字幕在 1080p 屏上约 40 px，反推得 40 / 0.675 ≈ 59 → **取 60**；
3. 上限被最长那句顶着：「风起则人畜惛迷，因以成病。」14 个字 ≈ 14 × 60 = 840 px，
   占 1600 的 53%——一行放得下，还留一半空；
4. 一句话说清楚：**字幕要占屏高的 5%~7%**（60 / 900 = 6.7%）。
   原来那版 19 px 是 2.1%，手机上当然看不清。

还有一条同样重要：**描边**。暖白的字压在被太阳照亮的沙面上，对比度本来就不够，
所以字幕和题记都加了暗褐色的 `outline_size`（不是纯黑——纯黑是从画面里抠出一行字，
暗褐只是给字一个落脚的地方）。题记跟着放大到 54/30/26，不然"最后一句话"会比
途中的自言自语还小。

### 声音：两条路，别都塞进混音器

**Web 上 Godot 的混音器是主线程在跑。** 不开 Thread Support 时，
`platform/web/audio_driver_web.cpp` 的 `_process_callback` 就在主线程里调
`audio_server_process`，每 128 帧一个 render quantum，靠 AudioWorklet 的
postMessage 往返供数据。渲染一忙，喂不上就丢一个 quantum——听感就是
**音乐被拖慢、发飘，像磁带被人按住**（"爆音"和"拖慢"是同一件事的两个量级）。

所以按播放类型分派（`audio/general/default_playback_type` 的枚举 hint 实测是
`Stream,Sample`：**0 = Stream，1 = Sample**；节点上多一个 0 = Default）：

| 层 | 播放类型 | 谁在播 | 为什么 |
|---|---|---|---|
| BGM（74 s 循环） | **Sample** | 浏览器原生的 `AudioBufferSourceNode` | 解码在**加载时一次做完**（74 s 立体声约 26 MB 的 AudioBuffer），播放期间主线程一次都不插手——结构上不可能被渲染拖慢 |
| 喘气 / 风声 | **Stream** | Godot 混音器 | 它们是 `AudioStreamGenerator` 现场合成，只有混音器能播 |

缓冲还有一条余量：`audio/driver/output_latency.web=100`（默认 50）。
`buffer_length = closest_power_of_2(latency × mix_rate / 1000)`，
48000 Hz 下 50 ms → 2048 帧（42.7 ms）、100 ms → 4096 帧（85.3 ms）——
留给混音器上的那两层一倍余量。

改之前 / 改之后（有头 Chrome，同一台机器，24 秒连续行走，`AnalyserNode`
抓真实输出波形 + 输出包络与 BGM 原文件做互相关）：

| 指标 | 改之前（线上那份） | 改之后 |
|---|---|---|
| `createBufferSource` 调用次数 | 0（BGM 在混音器上） | 1（BGM 交给浏览器） |
| 24 s 行走里最长的纯静音段 | 384 样本 ≈ 8 ms（丢了一个 quantum） | **0** |
| BGM 播放速率（互相关） | 1.0000× | 1.0000× |
| 输出 RMS | 0.156 | 0.217 |

本机这台机器上"拖慢"复现不出来（速率正好 1.0000），这本身也是证据：
**它是载荷相关的**——主线程越忙，丢的 quantum 越多。把 BGM 挪出混音器
之后，音乐就不再受这件事影响。喘气/风声还留在混音器上（生成器只能 Stream），
但它们是连续的氛围声，偶尔丢一个 quantum 听不出来。

还嫌不够的话，下一级开关是 **Thread Support**：`export_presets.cfg` 里
`variant/thread_support=true`，混音会搬到一条独立 pthread 上
（`AudioDriverWorklet::_audio_thread_func`），代价是必须要 COOP/COEP——
少一个头，整个游戏起不来，所以没默认打开。

`tools/probe_web_audio.py <url> <out-dir> [宽 高] [--headed] [--bgm=<mp3>]`

## 和 Blender 概念图的关系

`blender/` 里的塔克拉玛干和这里的 3D 世界**共用同一套沙丘公式**：

- Blender：[desert_lib.py](blender/desert_lib.py) 的 `dune_height()`
- Godot：[dune_field.gd](scripts/world/dune_field.gd) 的 `sample()`

参数名（`height` / `sharp` / `spacing` / `bend` / `swell` / `vary`）一一对应。
Blender 的 5 张氛围图就是这一关的美术方向。

**但相位和取值是故意分开的**：Blender 那边是离线概念图，用 `* PI`
（脊距 = 2 × spacing）、大丘缓坡；Godot 这边是玩家真的要用两条腿走完的一局，
用 `* TAU`（脊距 = spacing），`spacing` / `height` / `swell` 都按
"三分钟翻四道脊"重新定过。改这几个数之前先看 `[体力契约]` 那条测试。

坐标约定：**脊线沿 Z 延伸、沿 X 排列**。相机要朝 ±X 看才能看到一道道叠过来的
沙丘，朝 Z 看只会看到一条条平线。这条在 Blender 端踩过坑，现在有测试守着
（测试里的 `[脊线方向]` 一节）。

## 踩过的坑

完整版在 [blender/README.md](blender/README.md)，这里挑几条跨端的：

1. **Blender 的体积雾是死路。** 世界体积会让画面全黑（阳光在无限光程上被吃光）；
   有限体积盒更怪——纯透明、没挂体积着色器的大盒子也会让地形完全不受光。
   最后改用"渐变沙尘天空 + 材质距离雾"。
2. **Godot 的 sky shader 里没有 `SUN_DIR`**（那是 Blender 的），太阳方向得自己传。
3. **天空噪声别做透视除法**（`dir.xz / dir.y`）：地平线附近 uv 爆掉，
   天空会浮出一块块三角分面。
4. **`var x := some_variant.instantiate()` 会解析失败**；而解析失败后 Godot
   没有主场景可跑，进程会一直挂着——表面看像死锁，实际是脚本根本没加载起来。
5. **`CanvasLayer` 不是 Control**，没有 `size` 也没有 `NOTIFICATION_RESIZED`，
   准星居中要用 CenterContainer 而不是自己算坐标。
6. **`phase = (x / 间距) * PI` 的脊距是 2 × 间距。** `cos` 的周期是 2π，
   写 PI 等于让周期翻倍。名字、注释、测试三处都在说 95 m，实际是 190 m，
   而"三分钟翻四道脊"的契约就是被这 2 倍吃掉的。
7. **用 `set_anchors_preset` 给 Label 定位，缩到角落之后它是按自己的最小尺寸算的。**
   沙暴那行字当时只有几个字宽，于是正好压在"体力"上——截图里就是"文字交叠"。
   要整行宽就得 `set_anchors_and_offsets_preset(PRESET_TOP_WIDE)`。
8. **"测试没打印汇总"曾经不是输出问题，是真崩了。** 测试收尾偶尔少了
   `ALL TESTS PASSED` 一行、退出码变成 `0xC0000005`，我第一反应是
   "Godot 退出时丢了 stdout 缓冲区"，还试过在 `quit()` 前多等一帧——
   结果反而每次都崩。真正的原因是**测试顺序**：最后一节要建一整座世界，
   而它前面已经拆过好几座（每拆一次 Mirage 就是几千个 MeshInstance3D），
   headless 下"拆了又建"约有一半概率崩在 `add_child` 上。
	把最重的那一节挪到进程最干净的时候跑，连跑 5 次全绿。
   **教训：症状（缺汇总）离原因（测试顺序）隔了三层，"我以为"的那层先别信。**
9. **截图工具的 `--tired` 静默失效了两轮。** 它在 `_ready` 里写
   `GameState.stamina`，而 `main._ready()` 紧接着调 `GameState.reset()`
   把体力恢复成满的——于是 `--tired` 拍出来和开局一模一样（连
   `strength=0.57` 都一模一样），我拿它当"幻影很实的样子"看了半天。
   探针要写的东西，**得在每帧写**（`_pin_stamina`），不能只在初始化时写一次。
10. **"佛塔被佛挡住"不能用包围盒量。** 像身的包围盒最宽处在 0.55h 的举臂
    那一层，早就在画面上沿之外；拿它当"像的右缘"会得到 +31°，把整座城都
    逼出画面。要量的是**画面上确实看得见的那一段**（水平前视是 0~0.25h），
    按顶点逐条筛出来再取最大 z——量出来是 0.156h，和肩半宽 0.152h 几乎一样，
    所以诊断里直接拿肩半宽当代理。
